## 1. Identity, Access & Platform Threats (T-01 .. T-15)

| Threat ID | Threat Description & Attack Path | Countermeasure / Security Control | Verification Evidence | Residual Risk |
| :--- | :--- | :--- | :--- | :--- |
| **T-01** | **Unauthenticated Access:** Attacker sends requests to protected routes without a valid Firebase Auth session. | `AuthorizationService` immediately returns `UNAUTHENTICATED` decision; Firestore Security Rules default deny anonymous reads. | `Suite 1: Unauthenticated DENY` & `Rules: Anonymous protected org read (DENY PASS)` | **LOW** |
| **T-02** | **Cross-Organization Read:** User in Org A attempts to inspect projects, members, or metadata of Org B. | Firestore rule helper `isOrgMember(orgId)` verifies active membership in target organization; `AuthorizationService` rejects `ORGANIZATION_NOT_FOUND`. | `Suite 1: Cross-org DENY` & `Rules: Cross-org read (DENY PASS)` | **LOW** |
| **T-03** | **Cross-Project Read:** Member in Org A assigned to Project A attempts to read security metadata of Project B. | Firestore rule helper `hasProjectAccess(orgId, projectId)` checks active project assignment; `AuthorizationService` evaluates `PROJECT_ACCESS_MISSING`. | `Suite 1: Missing project assignment DENY` & `Rules: Cross-project read (DENY PASS)` | **LOW** |
| **T-04** | **Self Role Escalation:** Standard member alters their role payload to grant themselves `ORG_OWNER` or `PROJECT_ADMIN`. | Client writes directly to `members` and `projectAccess` are denied in Security Rules (`allow write: if false;`); trusted functions validate server-side caller role and reject self-elevation. | `Suite 2: Self-promotion (DENY PASS)` & `Suite 3: Role escalation prevention` | **LOW** |
| **T-05** | **Privileged Role Escalation:** Non-owner admin attempts to create a new `ORG_OWNER` or assign `PLATFORM_ADMIN`. | `TrustedSecurityCommandsEngine` validates caller is `ORG_OWNER` or `PLATFORM_ADMIN` before allowing owner role assignment. | `Suite 3: Server-side caller authorization verification` | **LOW** |
| **T-06** | **Direct Firestore Rule Bypass Attempt:** Attacker calls Firestore REST/SDK endpoints directly to alter data. | Declarative Firestore Security Rules with default deny on all root collections and explicit subcollection matching. | `Suite 2: Rules default deny present` | **LOW** |
| **T-07** | **Direct Audit Event Mutation / Erasure:** Malicious user tries to modify or delete logs covering security changes. | Security Rules enforce `allow create, update, delete: if false;` on `organizations/{orgId}/auditEvents`; only trusted server functions append. | `Suite 2: Client audit CREATE/UPDATE/DELETE (DENY PASS)` | **LOW** |
| **T-08** | **Stale / Revoked Membership Access:** Previously authorized user whose membership was revoked continues calling endpoints. | Auth ID token may remain valid at auth provider layer, but authorization is strictly denied on every request by `status == 'ACTIVE'` verification in `AuthorizationService` and Firestore Security Rules. | `Suite 1: Revoked membership DENY` & `Rules: Revoked membership read (DENY PASS)` | **LOW** |
| **T-09** | **Suspended User Access:** User marked as `SUSPENDED` attempts to access venture workspaces. | `AuthorizationService` checks `UserProfile.status === 'ACTIVE'` and Firestore rules verify `isUserActive()`. | `Suite 1: Suspended-user DENY` & `Rules: Suspended User Direct Firestore Read (DENY PASS)` | **LOW** |
| **T-10** | **Confidentiality Metadata Bypass:** External reviewer lacking `data_room.read_confidential` attempts to view confidential documents. | `AuthorizationService` maps confidentiality levels (`CONFIDENTIAL`, `HIGHLY_CONFIDENTIAL`) to explicit required capabilities. | `E2E 25: Data Room Confidential Permission PASS` & `E2E 26: Data Room Highly Confidential Denied PASS` | **LOW** |
| **T-11** | **Static Confidential Asset Exposure:** Non-public Data Room binary documents are bundled into public static assets. | Build-time and CI Sensitive Static Asset Scanner validates `dist/` contains 0 internal/confidential files; pending assets use `SECURE_STORAGE_PENDING`. | `Suite 6: Sensitive static asset scan` | **LOW** |
| **T-12** | **Service Credential Leakage:** Firebase Admin or service account private keys committed to repository or client bundles. | Automated Secret Scanner checking RSA keys, service account JSONs, and provider tokens across code. | `Suite 7: Secret scan` | **LOW** |
| **T-13** | **Client Token Leakage via Logs:** Logging system captures user passwords, auth tokens, or session keys in plain text. | `logger` sanitizes inputs and prohibits logging authorization credentials or session tokens. | Automated secret scanner test & Architecture review | **LOW** |
| **T-14** | **Broad Unsafe Firestore Query:** Client queries root collections without tenant filters attempting to scrape cross-tenant data. | Security Rules disallow root collection group queries; queries must be path-scoped to `organizations/{orgId}`. | `Suite 2: Rules default deny present` | **LOW** |
| **T-15** | **AI Context Access Outside Authorization Scope:** Copilot attempts to read projects or claims for which the user lacks permissions. | AI Copilot execution inherits the active caller's `SecurityContext`; AI cannot make security decisions or bypass RBAC. | `Suite 4: E2E 23: Copilot Permission` | **LOW** |

## 2. Secure Storage & Controlled Sharing Threat Catalog (T-16 .. T-30)

| Threat ID | Canonical Threat Name & Description | Countermeasure / Security Control | Verification Evidence | Residual Risk |
| :--- | :--- | :--- | :--- | :--- |
| **T-16** | **Anonymous Storage Object Read:** Anonymous attacker attempts direct GET on raw object URL. | `storage.rules` default deny; `isAuthenticated()` required on all paths. | `Storage Rules 1: Anonymous secure file read (DENY PASS)` | **LOW** |
| **T-17** | **Cross-Organization Storage Read:** User in Tenant A attempts to download binaries from Tenant B path. | Storage rule helper `isOrgMember(orgId)` matches path `{orgId}` against active membership. | `Storage Rules 4: Cross-org secure file read (DENY PASS)` | **LOW** |
| **T-18** | **Cross-Project Storage Read:** User in Org A attempts to download binaries from unassigned Project B. | Storage rule helper `hasProjectAccess(orgId, projectId)` verifies project membership. | `Storage Rules 6: Cross-project secure file read (DENY PASS)` | **LOW** |
| **T-19** | **Unauthorized Upload:** Viewer or unauthorized actor attempts upload to storage bucket. | Storage rules enforce `getProjectRole(orgId, projectId) in ['PROJECT_ADMIN', 'PROJECT_EDITOR']`. | `Storage Rules 8 & 9: Viewer upload (DENY PASS) & Editor upload (ALLOW PASS)` | **LOW** |
| **T-20** | **Oversized Upload:** Malicious user attempts to upload payloads exceeding policy limits. | `UploadPolicy` and `storage.rules` enforce `request.resource.size <= maxBytes` (50MB/20MB/10MB). | `Storage Rules 17: Oversized upload (DENY PASS)` | **LOW** |
| **T-21** | **Disallowed Media Type Upload:** Attacker attempts to upload executable or untrusted MIME types. | `UploadPolicy` allowlist and `storage.rules` `isAllowedMediaType()` constraint. | `Storage Rules 18: Disallowed media type upload (DENY PASS)` | **LOW** |
| **T-22** | **Direct Client Object Delete:** Client attempts direct storage object deletion bypassing governance. | Storage rules enforce `allow delete: if false;`; deletions require trusted function `DeleteSecureFile`. | `Storage Rules 19: Client direct object delete (DENY PASS)` | **LOW** |
| **T-23** | **Revoked Share Grant Access:** External reviewer attempts download using a revoked `ShareGrant`. | `StorageAuthorizationService` evaluates `grant.status === 'REVOKED'` and denies access. | `Storage Rules 23: Revoked share grant read (DENY PASS)` | **LOW** |
| **T-24** | **Expired Share Grant Access:** External reviewer attempts download after grant expiration. | `StorageAuthorizationService` checks `expiresAt <= now` and rejects `SHARE_GRANT_EXPIRED`. | `Storage Rules 22: Expired share grant read (DENY PASS)` | **LOW** |
| **T-25** | **Share Scope Escalation:** External reviewer with `SELECTED_FILES` grant attempts access to ungranted files. | `StorageAuthorizationService` verifies `fileIds.includes(file.id)` and returns `SHARE_SCOPE_MISMATCH`. | `Storage Rules 24: Out-of-Scope file via share (DENY PASS)` | **LOW** |
| **T-26** | **Confidentiality Ceiling Bypass:** Reviewer attempts to read documents exceeding grant's ceiling. | `StorageAuthorizationService` enforces hierarchical ceiling check. | `Storage Rules 25: Confidentiality ceiling exceeded (DENY PASS)` | **LOW** |
| **T-27** | **Stale Download Access:** Suspended user or inactive membership attempts download with valid auth token. | Live `isUserActive()` and `isOrgMember()` evaluation in `storage.rules` on every request. | `Storage Rules 3: Suspended user secure file read (DENY PASS)` | **LOW** |
| **T-28** | **Sensitive Browser Cache Persistence:** Sensitive binaries saved in `localStorage`, `sessionStorage`, or `IndexedDB`. | Ephemeral in-memory RAM delivery policy; Persistence Scanner validates 0 entries. | `Suite 6: Sensitive browser persistence scan (0 persistent entries)` | **LOW** |
| **T-29** | **Object Metadata Forgery:** Client tampers with intent or uploads metadata with mismatched tenant/size/type. | `FinalizeUpload` verifies caller tenant, matches intent metadata, and rejects forged payloads. | `Storage Rules 26: Metadata tenant mismatch (FINALIZATION REJECTED / DENY PASS)` | **LOW** |
| **T-30** | **Version Overwrite / History Destruction:** Attacker attempts in-place overwrite of Version 1 binary or version record. | `storage.rules` `allow update: if false;`; new version creates new immutable path `versions/ver-2/`, Version 1 preserved unchanged. | `Storage Rules 19 & Suite 1: Direct overwrite Version 1 DENY & History preserved PASS` | **LOW** |

## 3. Organization & Project Administration Threat Catalog (T-31 .. T-45)

| Threat ID | Canonical Threat Name & Description | Countermeasure / Security Control | Verification Evidence | Residual Risk |
| :--- | :--- | :--- | :--- | :--- |
| **T-31** | **Unauthorized Organization Administration:** Standard member attempts to rename org, change settings, or suspend org. | `TrustedAdministrationCommandsEngine` checks caller has `organization.update_settings` or `organization.suspend`. | `Command: UpdateOrganizationSettings (DENY PASS)` | **LOW** |
| **T-32** | **Unauthorized Project Creation:** User without `projects.create` capability attempts to initialize a project in an org. | `CreateProject` command checks active membership in target org and `projects.create` capability. | `Command: CreateProject (DENY PASS)` | **LOW** |
| **T-33** | **Last Owner Removal / Organization Orphaning:** Malicious admin removes, suspends, or downgrades the sole active `ORG_OWNER`. | `LifecyclePolicy` and trusted commands enforce `OWNER_PROTECTION` invariant, prohibiting removal of sole owner. | `Domain: Last owner remove/suspend (DENY PASS)` | **LOW** |
| **T-34** | **Cross-Organization Ownership Transfer:** Org owner attempts to transfer ownership to a user outside the organization. | `TransferOrganizationOwnership` validates target user has active `OrganizationMembership` in target org. | `Command: TransferOrgOwnership cross-org (DENY PASS)` | **LOW** |
| **T-35** | **Unauthorized Project Ownership Transfer:** Non-admin or editor attempts to transfer project ownership to another user. | `TransferProjectOwnership` validates caller is `PROJECT_ADMIN`, `ORG_OWNER`, or `PLATFORM_ADMIN`. | `Command: TransferProjectOwnership unauthorized (DENY PASS)` | **LOW** |
| **T-36** | **Invalid Project Lifecycle Transition:** Client attempts illegal transition such as `ARCHIVED` $\rightarrow$ `PAUSED` or `DRAFT` $\rightarrow$ `PAUSED`. | `LifecyclePolicy.validateProjectTransition()` permits only governed transitions and rejects illegal paths. | `Domain: Invalid transition (DENY PASS)` | **LOW** |
| **T-37** | **Paused Project Write Bypass:** User attempts to edit Project Twin, add claims, upload files, or create shares in a `PAUSED` project. | Application facades and `LifecyclePolicy.canWriteProject()` block all mutations while project is `PAUSED`. | `Domain: Paused Project Twin edit / upload / share (DENY PASS)` | **LOW** |
| **T-38** | **Archived Project Write Bypass:** User attempts to perform write mutations on an `ARCHIVED` project. | `LifecyclePolicy` denies normal writes for `ARCHIVED` projects while permitting authorized historical reads. | `Domain: Archived normal write / upload (DENY PASS)` | **LOW** |
| **T-39** | **Module Disable Bypass:** User attempts to invoke Data Room or Copilot operations when the module flag is disabled in `ProjectSettings`. | `ModuleEnablementPolicy` checks feature flag on project and denies execution when disabled. | `Domain: Disabled module access (DENY PASS)` | **LOW** |
| **T-40** | **Usage Cross-Tenant Leakage:** User in Org A requests usage statistics belonging to Org B or unassigned Project B. | `GetOrganizationUsage` and `GetProjectUsage` enforce tenant scoping and active project access checks. | `Suite 3: Usage cross-tenant check (DENY PASS)` | **LOW** |
| **T-41** | **Health Diagnostic Secret Leakage:** Health diagnostic endpoint returns stack traces, internal paths, or API keys. | `PlatformHealthPort` and health adapter sanitize all error codes, stripping tokens, credentials, and stack traces. | `Suite 8: Health error sanitization (PASS)` | **LOW** |
| **T-42** | **Platform Admin Cross-Tenant Abuse:** Non-platform admin attempts global summaries or tenant override without `PLATFORM_ADMIN` claim. | Legitimate `PLATFORM_ADMIN` has verified claims to inspect platform summary; unauthenticated, forged, or standard tenant callers attempting global access are rejected fail-closed. | `Suite 3: Platform Admin Legitimate (ALLOW PASS) & Non-Platform Admin (DENY PASS)` | **LOW** |
| **T-43** | **Administrative Audit Mutation:** Client attempts direct mutation or deletion of administrative audit events. | Security Rules enforce `allow create, update, delete: if false;` on `auditEvents`; trusted functions append only. | `Rules: Client audit mutation (DENY PASS)` | **LOW** |
| **T-44** | **Stale Project Context After Organization Switch:** UI preserves active project ID from Org A after user switches to Org B. | `window.VentureHubBridge.setActiveOrganization()` clears `currentProjectId` and resets `AdministrativeContext`. | `E2E 17: Organization Switch Clears Project Context (PASS)` | **LOW** |
| **T-45** | **Project Slug Collision / Tenant Confusion:** Attacker attempts to create duplicate slug in same org to hijack routing. | `CreateProject` verifies slug uniqueness within the target organization (`organizationId + projectSlug`). | `Domain: Duplicate project slug (DENY PASS)` | **LOW** |

## 4. Production Hardening, Observability & Deployment Threat Catalog (T-46 .. T-60)

| Threat ID | Canonical Threat Name & Description | Countermeasure / Security Control | Verification Evidence | Residual Risk |
| :--- | :--- | :--- | :--- | :--- |
| **T-46** | **Staging/Production Environment Mix-Up:** Developer accidentally deploys staging configuration or test credentials to production. | `EnvironmentGuardPolicy.validateEnvironment()` blocks build if credentials or project IDs match staging in a production target. | `Suite: Environment isolation & separation (PASS)` | **LOW** |
| **T-47** | **Production Emulator Endpoint Exposure:** Production client bundle connects to localhost or emulator endpoints. | `EnvironmentGuardPolicy` scans production config for `localhost`, `127.0.0.1`, `demo-` and fails-closed. | `Suite: Production emulator scan (0 endpoints PASS)` | **LOW** |
| **T-48** | **Missing CSP / Script Injection Expansion:** Malicious third-party scripts injected via CDN or inline script execution. | Strict `Content-Security-Policy` with locked `script-src` and `object-src 'none'`. | `Suite: CSP negative origin tests (DENY PASS)` | **LOW** |
| **T-49** | **App Check Bypass / Missing Enforcement:** Bot or unauthorized client queries backend directly without valid App Check token. | Firebase App Check enforced on Firestore, Storage, and Functions with fail-closed denial on invalid tokens. | `Suite: App Check invalid token (DENY PASS)` | **LOW** |
| **T-50** | **Production Secret Leakage:** Server credentials or API keys accidentally committed or embedded in client bundles. | Automated Secret Scanner Gate runs pre-commit and in CI on all bundle outputs. | `Suite: Secret scan gate (0 secrets PASS)` | **LOW** |
| **T-51** | **Unsafe Deployment Without Approval:** Continuous integration automatically releases unreviewed code to production. | GitHub Actions `deploy_production` environment configured with mandatory human review gate. | `CI/CD: Human production approval gate (PASS)` | **LOW** |
| **T-52** | **Deployment Artifact Drift:** Recompilation during production release produces bytecode differing from verified staging artifact. | Single immutable build artifact produced in CI and promoted to staging and production. | `ADR-0100: Immutable deployment artifact (PASS)` | **LOW** |
| **T-53** | **Rollback Failure:** Rollback procedure fails due to missing previous artifacts or database migration lock. | Documented rollback runbook tested across Hosting, Functions, and Rules to version $N-1$. | `Suite: Rollback verification (PASS)` | **LOW** |
| **T-54** | **Backup Exists But Restore Fails:** Database backups are taken but cannot be restored due to corruption or schema mismatch. | Mandatory staging restore exercise executed and verified against restored data counts. | `Suite: Backup staging restore exercise (PASS)` | **LOW** |
| **T-55** | **Logging Sensitive Tokens:** Structured logger captures passwords, JWT tokens, signed URLs, or confidential document content. | `LogRedactionPolicy` deeply sanitizes all metadata and message strings before log output. | `Suite: Log redaction zero-leakage gate (0 leaked PASS)` | **LOW** |
| **T-56** | **Alerting Blind Spot:** Production outages or auth spikes occur unnoticed due to missing operational metric alerts. | Seven operational metric domains instrumented with four alert classes (`CRITICAL`, `HIGH`, `MEDIUM`, `INFO`). | `Suite: Observability & alert class coverage (PASS)` | **LOW** |
| **T-57** | **Unbounded Retry Duplicate Mutation:** Network timeout causes retry loop that duplicates state-mutating operations. | `IdempotencyPolicy` tracks request IDs for critical administrative commands within a 24-hour window. | `Suite: Idempotency replay protection (PASS)` | **LOW** |
| **T-58** | **AI Request Abuse / Cost Explosion:** Malicious actor or loop consumes excessive AI generation tokens. | Copilot request guard enforces rate limits per session, max context windows, and bounded retries. | `Suite: AI cost guardrails (PASS)` | **LOW** |
| **T-59** | **Public Cache Exposure of Sensitive Content:** Sensitive binary files cached on public CDN edges. | Non-cache headers enforced for authenticated routes; public cache limited to fingerprint-hashed static media. | `Suite: Sensitive static asset scan (0 non-public in CDN PASS)` | **LOW** |
| **T-60** | **Dependency / Supply Chain Compromise:** Vulnerable or malicious third-party npm package introduced into codebase. | Automated npm dependency audit and lockfile integrity verification in CI. | `Suite: Dependency vulnerability audit (0 critical PASS)` | **LOW** |
